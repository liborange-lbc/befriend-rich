# 技术决策记录

## D001 - 推迟交易记录明细和分红/拆分处理

**日期**: 2026-04-24
**状态**: 已决定

**背景**: 原始规划中 #5 交易记录明细和 #4 分红/拆分处理被列为数据基础层功能。

**决定**: 推迟这两个功能到后续版本。

**原因**:
1. 当前数据源（微众银行对账单、支付宝业务凭证）只提供周维度持仓快照，不包含逐笔交易流水
2. 分红数据需要额外数据源（如天天基金网分红公告），当前未接入
3. 强行构造交易记录（从快照差值推算）会引入不准确数据，违背数据质量原则
4. 收益归因分析可以基于现有周快照数据计算时间加权收益率，不强依赖逐笔交易

**影响**: 收益归因分析将基于周快照差值计算，精度为周级别而非日级别，对个人投资者场景足够。

## D002 - Phase 1 聚焦基础设施而非数据模型

**日期**: 2026-04-24
**状态**: 已决定

**背景**: 原始 Phase 1 包含交易记录和分红处理（数据模型变更），现调整为基础设施功能。

**决定**: Phase 1 改为数据备份 + 数据源健康监控，这两个功能独立性强、风险低、立即可用。

**原因**:
1. 数据备份是安全底线，应最先实现
2. 数据源监控为后续所有数据依赖功能提供质量保障
3. 这两个功能不涉及核心数据模型变更，风险低

## D003 - 实施顺序优化

**日期**: 2026-04-24
**状态**: 已决定

**决定**: 按依赖关系重新排序：
1. Phase 1: 数据备份、数据源监控（基础设施）
2. Phase 2: 基金比较、相关性分析、收益归因（分析功能，前两个为归因提供基础组件）
3. Phase 3: 估值指标、再平衡、定投增强（策略功能，估值为再平衡和智能定投提供信号）
4. Phase 4: 投资日记、数据导出（运营功能，依赖前面的分析结果）
5. Phase 5: 移动端适配（UX层，最后做确保适配所有已实现功能）
